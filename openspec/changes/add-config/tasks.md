# Tasks

Priorities: groups 1-18 are P1 (config loads once), 19-23 are P2 (reload), 24 is integration only. Test names, files and kinds are in design.md (Test Strategy); every test there appears in exactly one RED task, and no RED task needs a symbol or behavior from a later group. Root tests run with `go test -race -run ... .`, config-module tests with `cd config && go test -race -run ... ./...`. In a synctest bubble a RED test waits with `select` on its result channel and `time.After` inside the bubble, so it fails with an assertion, never a bubble deadlock; `testWithTimeout` still wraps it from outside the bubble. "Passes on arrival" tests are proven able to fail by a temporary change that is not committed, and the commit message records it.
